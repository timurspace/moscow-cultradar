# Культрадар

Публичная московская культурная афиша с широким покрытием и редакционными метками: музыка, театр, опера / балет, лекции и разговоры.

Сайт: https://timurspace.github.io/moscow-cultradar/

## Принцип отбора

Культрадар не должен решать за пользователя, что ему «достойно» смотреть. База собирает широкий подтверждённый слой событий по отслеживаемым площадкам, а редакционные поля (`editorial_status`, `featured`, `why`) помогают расставить акценты.

Кроссоверные, праздничные и популярные программы не исключаются автоматически только из-за жанра. Явные отмены и неподтверждённые даты в активную афишу не добавляются.

## Структура

- `index.html` — каркас интерфейса.
- `styles.css` — оформление.
- `app.js` — фильтры, карточки, личные статусы, заметки и календарь.
- `events.json` — публичные события.
- `sources.json` — физические площадки, группы мониторинга и discovery-источники.
- `validate.js` — машинный аудит данных.
- `PROJECT_HANDOFF.md` — подробное текущее состояние и правила продолжения проекта.

## Карточка события

Карточка показывает дату, раздел, площадку, редакционный статус, программу / её статус, исполнителей, билетный статус и объяснение `why`.

Короткие обозначения залов (`БЗК`, `МЗК`, `КЗЧ` и т. п.) кликабельны: нажатие фильтрует афишу по соответствующей площадке. Повторное нажатие снимает фильтр.

Кнопка **«Открыть событие ↗»** ведёт на первичную официальную страницу события, когда она известна. Если отдельную страницу найти не удалось, используется официальный сайт площадки и кнопка **«Сайт площадки ↗»**.

Агрегатор можно использовать для обнаружения события, но его URL следует хранить отдельно как `discovery_url`, а не как основной `source_url`.

## Личные данные

Статусы `Собираюсь`, `Куплено`, `Позже`, `Пропустить`, `С Тимофеем`, `Был` и заметки хранятся только в `localStorage` браузера под ключом `afisha-private-v2`.

При отметке `Был` сохраняется приватный snapshot события. Ручной экспорт / импорт использует JSON-схему версии 4. Личные данные не записываются в публичный репозиторий.

## Календарь

Из карточки можно скачать `.ics` или открыть событие в Google Calendar. В календарное описание и URL также подставляется первичная ссылка события / площадки.

## Проверка данных

Локально:

```bash
node validate.js
node validate.js --md
```

GitHub Actions автоматически запускает аудит при изменениях `events.json`, `sources.json` и `validate.js` и сохраняет `audit-report.md` как artifact.

Аудит проверяет дубли ID, обязательные поля, даты, соответствие площадок `sources.venues`, наличие ссылок у датированных событий, очевидные агрегаторы в `source_url` и качество музыкального контекста.


## Эмблема и favicon

Основной знак проекта — **лира + театральная маска** с золотой дугой/звездой как мотивом обнаружения. Полная эмблема в `brand-emblem.svg` теперь использует напрямую утверждённый сгенерированный вариант 3, без ручной перерисовки. Для браузерной вкладки используется отдельный упрощённый `favicon.svg`, сохраняющий тот же силуэт, но рассчитанный на 16–32 px. Если после реального теста во вкладках он окажется недостаточно читаемым на 16 px, запасной вариант — более простой знак со скрипичным ключом.
