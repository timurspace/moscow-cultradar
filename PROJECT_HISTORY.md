# PROJECT HISTORY — «Культрадар»

> История завершённых этапов, миграций и прошлых состояний. **Не использовать старые counts отсюда как текущее состояние.** Для актуальной картины читать `PROJECT_STATE.md`.

## Архитектурные решения, которые пережили этапы

- Проект закреплён за `timurspace/moscow-cultradar`, public GitHub Pages из `main`/root.
- События отделены от интерфейса в `events.json`; registry источников — в `sources.json`.
- Редакционная модель изменилась от слишком короткого top к широкому подтверждённому календарю с `editorial_status` и отдельным `ticket_urgency`.
- Физическая площадка, organizer и discovery разведены по разным сущностям.
- Время не угадывается: при известной только дате используется `date_only`.
- При переносе события сохраняется стабильный id, если это возможно, чтобы не ломать приватный state.
- Публичный и приватный слои разделены: личные решения и заметки не попадают в GitHub.
- Сайт остаётся статическим: GitHub Pages + JSON + vanilla JS; усложнение стека не вводилось без необходимости.

## 2026-09-26 — основной этап формирования продукта

### Sources schema v2

`sources.json` разделён на:

- `venues`;
- `discovery_sources`;
- `monitor_entities`;
- `monitor_groups`.

Критическое правило: реальный venue в событии должен соответствовать физической площадке, а ensemble/СМИ/агрегатор не должен маскироваться под площадку. ClassicalMusicNews закреплён как обязательный первый discovery-проход.

После одного из контрольных аудитов в handoff был зафиксирован исторический snapshot **343 события**. Это только этап истории.

### Рост базы и контрольный snapshot

Позже 26.09 был зафиксирован snapshot **483 события** и **55 физических площадок**. Это состояние было актуально только в тот момент; последующие sweeps его превысили.

### Theatre sweep

Добавлены и расширены «Современник», «Около дома Станиславского», «Сфера», Маяковский, Театр Наций, «Внутри», Электротеатр и другие театральные контуры. После этого этапа handoff фиксировал **534 события** и **65 физических площадок**.

Важный вывод: ноль в будущем месяце нельзя считать отсутствием событий, если театр ещё не опубликовал афишу.

### Talks / Лекторий «Достоевский»

Создан отдельный organizer/discovery-контур Лектория «Достоевский». События начали публиковаться под фактическими площадками: музеями, библиотеками, КЗЧ и др. Сам Книжный клуб на Воздвиженке оставлен как отдельная физическая площадка мониторинга.

Good Talks Club оставлен обязательным discovery; один из проходов не смог надёжно прочитать его актуальную афишу, поэтому события не выдумывались.

### Private visited archive

Добавлен статус `visited` / «Был». При отметке сохраняется приватный snapshot события, появился отдельный раздел «Посещённое», поле «Что осталось?» и перенос прошедшего события из планов в историю.

Export schema приватных данных повышена до **v4**. `localStorage` key `afisha-private-v2` сохранён для совместимости.

### Плотность карточек

Добавлен переключатель 1 / 2 / 3 карточки в строке. Выбор сохраняется в `localStorage` под `cultradar-density-v1`; на mobile всегда одна карточка, на tablet режим 3 ограничивается двумя.

### Music card schema v2

Для music/opera введены `composers`, `works`, `venue_short`, `program_status`, `season`, `sales_status`, `card_schema_version: 2`.

Отдельно закреплено различие между:

1. событие опубликовано в сезоне;
2. доступно/было доступно по абонементу;
3. single tickets реально поступили в продажу.

Сделан дальний сезонный проход 2026/27 по опубликованному слою Филармонии, Консерватории и Зарядья. Отменённые события не добавлялись.

### Automation

Настроена weekly automation «Афиша: музыка, театр, опера и разговоры» с первым обязательным проходом ClassicalMusicNews и затем calendars sweep.

Старая automation «Билеты Норштейн—Клейман» закончила свой временной RRULE 22.09.2026 и впоследствии была отключена.

## 2026-09-27 — core music, brand и mobile fixes

### Brand / favicon

Финальный знак: лира + театральная маска + золотая дуга/звезда. Активные файлы `brand-emblem-v3.png` и `favicon-v3.png` используют один проверенный прозрачный PNG blob. Старые экспериментальные SVG удалены.

### Московская консерватория

Выполнен системный sweep БЗК, МЗК, Рахманиновского зала и зала Мясковского до 31.12.2026. Были добавлены десятки карточек и возвращены несколько кроссоверных/праздничных программ, которые ранний вкусовой фильтр отсёк слишком агрессивно.

Исправлены конкретные даты и программы; при переносах стабильные id сохранялись.

### Московская филармония

Сделан широкий baseline КЗЧ + Камерного зала до 31.12.2026. На одном промежуточном этапе два зала выросли со 110 до 162 событий.

Затем октябрь был повторно сверен по официальной месячной афише. Найдены два остаточных пропуска — «Восток и Запад» 16.10 и «Руст Позюмский и его музыка» 29.10. После их добавления текущий на тот момент count стал **739**.

Октябрь закрыт повторным sweep. Ноябрь и декабрь оставлены на отдельную повторную проверку, несмотря на уже существующий baseline.

### Source policy

Закреплён приоритет прямой официальной страницы события. Если она не найдена, разрешён официальный календарь/страница venue. Aggregator остаётся discovery, а не primary source.

Короткие названия залов стали кликабельными фильтрами.

### Mobile venue filter

Исправлена проблема, при которой fixed mobile panel площадок было неудобно закрывать. Добавлены крупные sticky controls сверху и снизу; touch targets увеличены до 44–50 px. Asset versions в `index.html` менялись для обхода browser cache.

## Почему история вынесена отдельно

Старый handoff рос как журнал работы и одновременно как инструкция. В результате закрытые задачи, старые counts, актуальные правила и следующий backlog выглядели одинаково важными. Новый порядок:

1. `PROJECT_HANDOFF.md` — вход и алгоритм продолжения;
2. `PROJECT_STATE.md` — только актуальное состояние;
3. `PROJECT_RULES.md` — стабильные правила;
4. `PROJECT_HISTORY.md` — этот исторический журнал.

Если история расходится с текущим GitHub, это ожидаемо: история описывает прошлое.
