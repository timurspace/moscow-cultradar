# 1. Что это за проект

«Культрадар» — публичная московская культурная афиша с редакционным фильтром и приватным пользовательским слоем.

Текущее состояние:
- GitHub user: timurspace
- repo: timurspace/moscow-cultradar
- branch: main
- visibility: public
- GitHub Pages: https://timurspace.github.io/moscow-cultradar/
- public brand: Культрадар
- текущие файлы: index.html, styles.css, app.js, events.json, sources.json, README.md
- этот handoff: PROJECT_HANDOFF.md

Ключевой принцип, который был скорректирован по ходу проекта:

**Не сводить афишу к нескольким «идеальным» событиям. Собирать широкий релевантный календарь, отсекать только явную ерунду, а важность показывать редакционным статусом.**

Сайт должен реально заменять ручной просмотр десятков афиш, но не становиться безразборным агрегатором.

# 2. Пользовательская задача

Пользователь хочет:
1. Не пропускать интересные события в Москве.
2. Видеть не только ближайшие 2–3 недели, но и дальний горизонт продаж.
3. Отдельно отслеживать музыку, театр, оперу, лекции/разговоры.
4. Видеть события по площадкам.
5. Быстро отмечать: собираюсь / куплено / позже / пропустить / с Тимофеем.
6. Хранить личные заметки до события и «Что осталось?» после.
7. Добавлять выбранное событие в календарь.
8. Не превращать культурную жизнь в FOMO: сильное событие не должно автоматически означать «покупать прямо сейчас».

# 3. Редакционная модель

## 3.1. Широкий пул, а не короткий топ

Ранние версии были слишком узкими: в events.json оставалось всего несколько карточек. Это было признано ошибкой.

Правильная модель:
- проходить площадки календарём, а не искать случайные «лучшие» события;
- сохранять широкий релевантный пул;
- не выкидывать событие только потому, что оно не «идеальное»;
- отсекать явный маркетинговый мусор;
- различать ценность редакционными статусами.

## 3.2. Редакционные статусы

- attention = ОБРАТИТЬ ВНИМАНИЕ
- candidate = СЕРЬЁЗНЫЙ КАНДИДАТ
- decide = ЛУЧШЕ РЕШИТЬ ЗАРАНЕЕ

Для спорного театра/разговора в будущем можно добавить отдельный статус «эксперимент / посмотреть самому».

## 3.3. Билетная срочность — отдельная ось

Текущие значения:
- none
- no_rush
- watch
- buy
- low
- soldout

Логика:
- сильное событие может иметь no_rush;
- среднее событие может иметь buy, если хорошие места быстро уходят;
- не смешивать «ценность» и «срочность».

# 4. Горизонты

near — ближайшие:
- музыка: примерно 2–3 недели;
- театр/опера могут попадать сюда раньше, если решение о билете нужно сейчас.

buy — купить заранее:
- редкие программы;
- малые залы;
- премьеры;
- фестивали;
- сильные составы;
- события, где хорошие места уйдут заранее.

far — дальний радар:
- музыка обычно 1–3 месяца;
- театр/опера обычно 2–4 месяца, при необходимости до 6;
- фестивали;
- циклы;
- watchlist.

Главная мысль: горизонт определяется не только датой события, но и датой принятия решения о покупке.

# 6. Музыкальный профиль

Основной интерес:
- академическая музыка;
- камерная музыка;
- старинная музыка;
- барокко;
- исторически информированное исполнительство;
- современная академическая музыка;
- XX век;
- редкий репертуар;
- необычные программы;
- сильные молодые исполнители;
- независимые площадки;
- содержательные межжанровые проекты.

Не нужно автоматически отбрасывать:
- неизвестные имена;
- маленькие площадки;
- студенческие проекты;
- экспериментальные форматы.

Обычно отсеивать:
- generic «мировые хиты»;
- рок-хиты в симфонической упаковке;
- generic candlelight;
- фоновую неоклассику;
- попсовые программы без содержательной причины;
- «шедевры мировой музыки» как маркетинговую оболочку, если программа тривиальна.

Rusconcert всё равно мониторить, потому что там длинный горизонт продаж и иногда хорошие события.
